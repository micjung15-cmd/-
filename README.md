# 배송 지연이 리뷰를 얼마나 깎는가

브라질 커머스 플랫폼 Olist의 공개 주문 데이터(2016–2018, 약 10만 건)로
**"낮은 리뷰 점수의 원인은 상품인가 배송인가"** 를 분해합니다.

분석은 주피터 노트북에서 SQL로 하고, 확정된 쿼리를 Streamlit 대시보드로 올립니다.

## 이 대시보드가 다른 점

숫자만 보여주는 대신, **모든 숫자 아래에 세 가지를 함께 붙였습니다.**

| | |
|---|---|
| 정의 | 이 숫자를 정확히 어떻게 계산했고 무엇을 제외했는가 |
| SQL | 방금 실행된 쿼리 원문 |
| 믿을 수 없는 구간 | 이 숫자를 근거로 삼으면 안 되는 조건 |

여기에 `데이터 신뢰도` 탭을 따로 두어 결합 단계별 표본 손실과 중복 처리 기준을 먼저 밝힙니다.
읽는 사람이 숫자를 검증할 수 있게 만드는 것이 목적입니다.

## 실행 방법

필요한 것은 **Python 3.10 이상** 뿐입니다. 데이터베이스 서버는 설치하지 않습니다.

```bash
pip install -r requirements.txt

# data/README.md 안내대로 CSV 8개를 data/raw/ 에 넣은 뒤

jupyter lab            # 분석:   notebooks/01 → 04 순서로
streamlit run app.py   # 대시보드
```

### DuckDB에 대해

설치하고 관리하는 데이터베이스가 아니라 **CSV에 SQL을 쓰게 해주는 라이브러리**입니다.
서버도 계정도 포트도 없고, 적재 과정도 없습니다. 결과는 바로 pandas DataFrame으로 나옵니다.

```python
import duckdb
duckdb.sql("SELECT * FROM 'data/raw/olist_orders_dataset.csv' LIMIT 5").df()
```

쿼리는 표준 SQL만 써서 PostgreSQL로 옮겨도 거의 그대로 동작합니다.

## 구조

```
sql/base.sql       뷰 정의. 지연 구간 같은 지표 기준이 여기 한 곳에만 있습니다
notebooks/         분석. SQL을 셀에서 바로 쓰고 결과를 DataFrame으로 받습니다
  01_데이터_품질_진단   이 데이터로 무엇을 말할 수 있는가
  02_지연과_리뷰        며칠부터 점수가 급락하는가  ← 핵심
  03_카테고리_셀러      어디부터 손대야 하는가
  04_재구매            답이 안 나올 수도 있는 질문
app.py             대시보드 (노트북에서 확정한 쿼리를 올리는 곳)
docs/METRICS.md    지표 정의서 — 각 숫자의 계산식과 제외 조건
docs/FINDINGS.md   발견 기록 — 확인한 것과 확인하지 못한 것
```

**설계 원칙: 숫자는 한 곳에서만 정의한다.**
지연 구간 같은 기준은 `sql/base.sql` 에만 있고 노트북과 대시보드가 모두 그것을 참조합니다.
같은 지표가 화면마다 다르게 나오는 일을 구조로 막습니다.
